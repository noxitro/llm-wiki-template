LLM Wiki を点検する。

## vault の場所

推測で探さず、次の順で決める。

1. 頼まれた文(スキルに渡された引数を含む)の先頭が `--vault <名前>` なら、その名前を使う。残りが本来の依頼になる。
2. 作業フォルダから親のフォルダへ順に `.llm-wiki.json` を探し、最初に見つかったものを読む。どこにも無ければ `~/.llm-wiki.json` を読む。
3. 1 の名前(無ければ `default`)を `vaults.<名前>.path` で引く。それが vault の場所。
4. ファイルが無い・名前が見つからないときは止まり、vault のフォルダで `setup` を実行して作業フォルダと紐づけるよう人に伝える(`setup.bat` か `./setup.sh <作業フォルダ>`)。
5. その場所に `AGENTS.md`・`index.md`・`log.md` が揃っていなければ vault ではない。止まって人に伝える。
6. vault が作業フォルダの外にあって読めない(許可されない)ときは、vault を追加のディレクトリとして許可するよう人に伝えて止まる(Claude Code と Copilot CLI は `--add-dir <vault>`)。シェルで無理に読み書きしにいかない。

## 手順

1. vault の `AGENTS.md`(規約)を読む。以降はその規約に従う。
2. **機械の点検**: vault で `python scripts/wiki_lint.py` を実行し、出力をそのまま受け取る。結果を自分の判断で言い換えたり、エラーを見逃したりしない。
3. **意味の点検**: 規約の「Lint」の 2 に挙げた項目を見る。
   - 本文と根拠の突き合わせは、できればサブエージェントなど、そのページを書いていない別のエージェントにやらせる。渡すのはページと `sources` の根拠ファイルだけにし、自分の結論は渡さない。
   - 「要再確認」のページ(`watch` の題材が変わった、`stale_after` を過ぎた)は、根拠を取り直して今も成り立つかを確かめる(コマンドを実行する・ファイルを開き直す・文書を開く)。
4. 結果を表で人に報告する: 種類 / 対象 / 内容 / 直し方の案。**ここで止まり、人の承認を待つ。承認の前に vault へ書かない**。
5. 承認された項目だけを、規約の「Lint」の 3 のとおりに直す。`log.md` に `**Lint**` の項目で残す。
6. 機械の点検をもう一度通し(エラー 0)、規約の「git」に従ってコミットする(`lint: <概要>`)。push はしない。

「知識の穴」や「次に聞くべき問い」は wiki に書かず、報告に挙げるだけにする。
