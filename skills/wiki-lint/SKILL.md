LLM Wiki を点検する。

- vault の場所は次の順で決める。
  1. 作業フォルダに `HARNESS.md` があり、その「環境」節に「wiki の clone 先」の行があれば、その値(作業フォルダからの相対パス)。チームで配る形。
  2. 無ければ `{{VAULT}}`(個人の vault。配る側でパスに置き換える)。
  どちらも無ければ、vault の場所を人に聞いて止まる。
- vault が読めない(作業フォルダの外で許可されていない)ときは、vault を読めるように起動し直すよう人に伝えて止まる(例: `--add-dir <vault>`)。シェルで無理に読みにいかない。

## 手順

1. vault の `AGENTS.md`(規約)を読む。以降はその規約に従う。
2. **機械の点検**: vault で `python scripts/wiki_lint.py` を実行し、出力をそのまま受け取る。結果を自分の判断で言い換えたり、エラーを見逃したりしない。
3. **意味の点検**: 規約の「Lint」の 2 に挙げた項目を見る。
   - 本文と根拠の突き合わせは、できればサブエージェントなど、そのページを書いていない別のエージェントにやらせる。渡すのはページと `sources` の根拠ファイルだけにし、自分の結論は渡さない。
   - 「要再確認」のページは、根拠を取り直して今も成り立つかを確かめる(コマンドを実行する・ファイルを開き直す・文書を開く)。
4. 結果を表で人に報告する: 種類 / 対象 / 内容 / 直し方の案。**ここで止まり、人の承認を待つ。承認の前に vault へ書かない**。
5. 承認された項目だけを直す。取り直した根拠は新しい `raw/` ファイルとして足し、既存の根拠は変えない。`log.md` に `lint` の見出しで残す。
6. 機械の点検をもう一度通し(エラー 0)、vault でコミットする(`lint: <概要>`)。push はしない。
   チームで配る形(vault の場所を `HARNESS.md` から読んだとき)は、既定ブランチに直接コミットせず、`lint/<YYYY-MM-DD>-<短い名前>` のブランチを切ってコミットする。push と MR は人が行う。

「知識の穴」や「次に聞くべき問い」は wiki に書かず、報告に挙げるだけにする。
